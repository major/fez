## What this is

`fez` is an agent-native management CLI for Fedora/RHEL. It drives
`cockpit-bridge` over its framed JSON protocol (spawns the bridge, opens
channels, delegates privilege escalation to it) and reaches remote hosts by
shelling out to the system OpenSSH client. Rust, edition 2021, MSRV **1.92**
(pinned in `rust-toolchain.toml` and `Cargo.toml`; keep both in sync on bump).

Crates.io package name is `rusty-fez` because `fez` is already taken. The
installed binary and library crate name stay `fez`.

**fez holds no state.** It never writes a state file, cache, lock, or
spool (no `/var/lib/fez`, no `XDG_STATE_HOME`, no temp snapshots). Every
invocation is self-contained: it reads live system state through the bridge,
acts, emits the envelope, and exits. The source of truth always lives in the
managed subsystem (systemd, dnf5daemon, NetworkManager, firewalld), never in
fez. When a feature seems to need memory across invocations, push that state
into the subsystem (e.g. firewalld's own runtime-vs-permanent split and
`runtimeToPermanent`) or recompute it on each call, rather than persisting it
in fez. The only thing fez writes is the append-only audit log, and that is a
sink, not state fez ever reads back.

## Commands

Use the Makefile, not raw cargo, for gated work. `make` defaults to `check`.

- `make check` - local one-shot gate: `lint test docs-coverage security`
- `make lint` - `cargo fmt --check` then `cargo clippy --all-targets -- -D warnings`
- `make test` - `cargo test` (unit + integration)
- `make coverage` / `make coverage-html` - lcov for Codecov / HTML report
- `make docs-coverage` - **requires the nightly toolchain** (`cargo +nightly`); enforces 100% docstring coverage via `scripts/docs_coverage.py`
- `make security` - supply-chain + dep hygiene: `deny machete`
  - `make deny` - `cargo deny check` (RUSTSEC advisories, license policy, banned/duplicate crates, source allow-list; config in `deny.toml`). Install: `cargo install cargo-deny --locked`
  - `make machete` - `cargo machete` (unused declared deps). Install: `cargo install cargo-machete --locked`
- `make msrv` - `cargo +1.92 check --all-targets`; proves the crate compiles on the pinned MSRV, not just stable. Requires `rustup toolchain install 1.92`
- Single test: `cargo test --test services name_of_test` (integration files are `tests/cli.rs`, `tests/mcp.rs`, `tests/packages.rs`, `tests/services.rs`, `tests/network.rs`)

## Gates (CI: `.github/workflows/ci.yml`, `.github/workflows/codeql.yml`)

All enforced; do not regress:

- **90% project** + **95% patch** test coverage (Codecov, `codecov.yml`)
- **100% docstring coverage**. Crate root denies missing docs; every `pub` item needs a doc comment, fallible methods need an `# Errors` section.
- `clippy -D warnings` and `cargo fmt --check`. Never add `#![deny(warnings)]` to source; that lint pressure lives in CI flags only.
- **MSRV build** (`msrv` job): `cargo +1.92 check --all-targets` must pass. The pinned MSRV is a contract, not a declaration.
- **Supply chain** (`security` job): `cargo deny check` (advisories/licenses/bans/sources via `deny.toml`) + `cargo machete` (unused deps). License allow-list is tight (Apache-2.0/MIT/Unicode-3.0/Unlicense); a dep with an unlisted license fails CI on purpose.
- **CodeQL** (separate `codeql.yml`, build-mode `none`): runs on push/PR to `main` and weekly. Rust's CodeQL extractor only supports buildless (`none`) extraction; `manual`/`autobuild` are rejected at init. Results land in the Security tab. Not part of the `make check` gate (needs the GitHub CodeQL runner), so it cannot be reproduced locally.

CI actions are SHA-pinned. When bumping an action, pin the new commit SHA and keep the `# vX.Y.Z` comment accurate.

## Architecture

Thin binaries over a library (`src/lib.rs` owns the module tree; `run()` is the single entry point). Key modules:

- `protocol/` - wire protocol to the bridge: `frame` (framed JSON), `message`, `client`
- `transport/` - `local` (spawns the bridge) and `ssh` (OpenSSH client) ways to reach it
- `capabilities/` - the actual commands fez runs (e.g. `services`, `packages`, `network`, `firewall`); `capability/` holds machine-readable descriptors of that surface
- `dispatch.rs` - routes parsed CLI to capabilities (private module)
- `cli.rs` - clap definitions plus `command()`/`parse()` (the registry-enriched command tree) and `raw_command()` (the bare derived tree). New top-level verbs beyond the capability commands: `fez guide` (agent contract; `--json` emits an `AgentGuide` envelope), `fez completions <shell>` (bash/zsh/fish), and hidden `fez man` (emits the `fez.1` roff page; packaging runs it during `%build`). `envelope.rs` - the `fez/v1` JSON response envelope
- `safety.rs` - guardrails: protected units refuse mutation without `--force`
- `audit.rs` - JSON-lines audit log of attempted + completed mutations (each executed mutation writes two records: attempt + result)
- `mcp/` - MCP server (`fez mcp`, JSON-RPC 2.0 over stdio)

Errors: single `FezError` enum (`src/error.rs`) with stable string `code()` and `exit_code()` mappings. Exit codes are part of the contract (e.g. protected-unit = 8, timeout = 5, bridge spawn/closed = 6, dbus = 7, dependency-missing = 9, dangerous-transaction = 10, access-denied = 11). E2E and integration tests assert on them; update tests when you touch the mapping.

## Testing quirks

- Shared integration scaffolding lives in `tests/common/mod.rs` (pulled in per suite via `mod common;`). It exports `fez_fake()` (command wired to the fake bridge), `fez_fake_quiet()` (same plus `FEZ_AUDIT=off`, used by `firewall.rs` via a `use ... as fez_fake` alias), `fez_plain()` (no bridge, for `cli.rs` CLI-surface tests), the `PKG_COLUMNS` `PackageList` header constant, and an RAII `AuditLog` guard (`new(label)` / `env_value()` / `records()`; removes its temp file on drop) used by the `services`/`packages` audit-record tests. Suite-specific helpers stay local (e.g. `fez_without_bridge`/`fake_transport` in `services.rs`, `fez_mcp` in `mcp.rs`, which wraps `fez_fake().arg("mcp")`). The `common/` subdir is a module dir, not its own test binary, so the suite count stays at 10.
- Integration tests drive a **fake bridge binary** (`src/bin/fake_bridge.rs`, built as `fez-fake-bridge`) instead of a real `cockpit-bridge`. Tests point fez at it via the `FEZ_BRIDGE` env var set to `env!("CARGO_BIN_EXE_fez-fake-bridge")`. The fake reports `chronyd` inactive and `sshd` active; assertions depend on that.
- Packages integration tests (`tests/packages.rs`) drive the same fake bridge over `org.rpm.dnf.v0` (dnf5daemon). `FEZ_FAKE_PLAN` selects the staged transaction plan the fake returns from `Goal.resolve` (`install`/`small`/`protected`/`cascade`, exercising the removal guardrails); `FEZ_FAKE_NO_DNF5` makes the fake report the daemon absent (`ServiceUnknown`) to exercise the exit-9 `dependency-missing` path.
- The fake bridge models **transparent escalation** over `cockpit.Superuser`. fez sends `init` with `superuser: "none"` (deferring escalation), so the fake just completes the handshake with its own `init` reply and **no** `superuser-init-done` (real cockpit only runs superuser negotiation, and only then fires `superuser-init-done`, when init carries an escalation request; a bare `superuser: "none"` never triggers it). The client treats the bridge `init` as handshake-complete and does not wait for `superuser-init-done` (waiting for it hangs against a real bridge). Escalation is driven later by the client: it reads the `cockpit.Superuser` `Bridges` property and calls `Start(name)` over the internal bus (`bus: "internal"`, object path `/superuser`, interface `cockpit.Superuser`) until one mechanism succeeds. The `Bridges` read goes through `Properties.Get`, whose single out-arg is a D-Bus variant, so the `as` value is variant-wrapped (`{"t":"as","v":[...]}`); the fake wraps it and the client unwraps via `variant_value` before iterating mechanisms. A fake that returned the bare array would mask a client that fails to unwrap and would silently see zero mechanisms (spurious exit 11). `FEZ_FAKE_BRIDGES` configures the fake's advertised mechanisms as an ordered `name:outcome` list (`sudo:ok`, `sudo:err,polkit:ok`, ...); a bare `name` defaults to `ok`. Unset defaults to a passwordless-sudo host (`sudo:ok`), so most tests escalate without ceremony; an explicitly empty value (`FEZ_FAKE_BRIDGES=""`) advertises no mechanism, so privileged channels are denied (exit 11). `FEZ_FAKE_DENY_PRIVILEGED` models a host where escalation succeeds but the policy still rejects the privileged channel mid-operation (the bridge closes it `access-denied` even after a successful `Start`). Real standalone `cockpit-bridge` (no `cockpit-system`) advertises **zero** superuser bridges, so privileged channels are denied; escalation requires `cockpit-system` (it ships the sudo/pkexec bridge definitions) plus either passwordless sudo or a polkit rule. fez does not supply sudo passwords. The runtime `FEZ_ESCALATION` knob overrides mechanism selection: `off` disables escalation, any other value forces that single mechanism with no fall-through.
- The fake bridge **rejects `a{sv}` option dicts whose values are not variant-wrapped** (`reject_unwrapped_options`), mirroring real cockpit-bridge: every value of an `a{sv}` argument must be `{"t":<sig>,"v":<value>}`, not a bare scalar, or the bridge raises a marshalling `TypeError`. dnf option dicts are built via the `options()`/`variant()` helpers in `capabilities/packages.rs` so this stays correct. If you add a dnf method that takes an options dict, route it through those helpers or the integration tests will fail with `InvalidArgs`.
- Network integration tests (`tests/network.rs`) drive the same fake bridge over `org.freedesktop.NetworkManager`. NM reuses the generic `Get`/`GetAll` property methods across many object types, so the fake's `nm_reply` dispatches by **object path** (manager, `Devices/<n>`, `IP4Config/<n>`, `IP6Config/<n>`, `ActiveConnection/<n>`, `DHCP4Config/<n>`), not by method name like the systemd/dnf surfaces; the dispatch loop routes any call whose path starts with `/org/freedesktop/NetworkManager` to it first. Canned topology from `GetDevices`: `enp1s0` (ethernet, activated, full IPv4/IPv6/active-conn/DHCP), `enp2s0` (ethernet, unavailable, null `"/"` IP configs to exercise the absent-config guard), `lo` (loopback, unmanaged but kept by the default type filter), and `veth0` (veth, unmanaged, hidden by default and shown only with `--all`). Every `a{sv}`/variant value is variant-wrapped (`{"t":<sig>,"v":<value>}`) like the systemd `GetAll` arm. The `network` capability is read-only (unprivileged `dbus_open`, no escalation). `network list` hides unmanaged virtual interfaces unless `--all`; `network show <device>` looks the device up by `Interface` name and returns exit 4 (`not-found`) for an unknown name.
- Firewall integration tests (`tests/firewall.rs`) drive the same fake bridge over `org.fedoraproject.FirewallD1`. The fake's `fw_reply` dispatches by object path **and interface**, mirroring real firewalld: the firewalld surface is split across interfaces, so a method called on the wrong interface yields `UnknownMethod`. This matters because `getZones`/`getServices`/`getPorts`/`getInterfaces`/`getSources` live on the **zone** interface (`org.fedoraproject.FirewallD1.zone`), while `getDefaultZone`/`listServices`/`queryPanicMode` and the mutations live on the **root** interface (`org.fedoraproject.FirewallD1`). A path-only fake that ignored the interface masked a real bug where fez called `getZones` on the root interface (issue #33); the interface-aware fake reproduces it. The permanent **config** interface (`config`/`config.zone`) is polkit-gated (firewalld's `PK_ACTION_CONFIG`/`config.info`, `auth_admin_keep` on both server and desktop installs), so the fake answers config reads **only on a privileged channel** and otherwise returns an `AccessDenied` D-Bus error; the fake tracks which channels were opened `superuser: "require"` in a `privileged_channels` set. fez therefore reads permanent config for drift over a privileged (escalated) channel, even in the otherwise-unprivileged `status` (issue #34). Canned topology: default zone `public`; zones `public`/`internal`/`drop`; runtime `public` carries `ssh`/`dhcpv6-client` services and `9090/tcp`, while permanent `public` lacks `9090/tcp`, so runtime-vs-permanent drift is non-empty out of the box (`status` reports `+port 9090/tcp`, and `confirm` has something to commit). Runtime `public` masquerade is also seeded on while permanent is off, so `status` likewise reports `+masquerade`. Runtime reads are unprivileged; the permanent-config read and all mutations escalate via the existing `FEZ_FAKE_BRIDGES` machinery (an empty value yields exit 11 on a mutating call **and on `status`**, since status now escalates for the permanent read). The firewall methods used take plain typed args, not `a{sv}` option dicts, so they need no variant wrapping in either direction. Test-only knobs: `FEZ_FAKE_NO_FIREWALLD` (the FirewallD1 service reports absent -> exit 9), `FEZ_FAKE_PANIC` (start in panic-on state), and `FEZ_FAKE_PORT_REMOVED` (drop `9090/tcp` from the runtime `public` zone, modeling the post-`remove-port` read). The protected-op guard (removing the session ssh service/port, any default-zone change, `panic on`, and a drift-discarding `reload`) refuses without `--force` (exit 8); session-criticality is derived live from `$SSH_CONNECTION` (server port) with `ssh` always treated as critical.apping in either direction. Test-only knobs: `FEZ_FAKE_NO_FIREWALLD` (the FirewallD1 service reports absent -> exit 9) and `FEZ_FAKE_PANIC` (start in panic-on state). The protected-op guard (removing the session ssh service/port, any default-zone change, `panic on`, and a drift-discarding `reload`) refuses without `--force` (exit 8); session-criticality is derived live from `$SSH_CONNECTION` (server port) with `ssh` always treated as critical.
- Envelope JSON is **compact** (`Envelope::to_json_string` uses `serde_json::to_string`, no spaces). Assert `--json` output with substrings like `"kind":"ServiceList"` (no space after the colon). Pretty-printed `"kind": "X"` passes against a stale local build but fails in CI's clean build.
- E2E (`test/e2e/run.sh`) provisions a real cloud host via Terraform, installs `cockpit-bridge`, and exercises the real transport. Expensive and destructive (auto-`destroy` on exit). It auto-`tee`s every run to `test/e2e/logs/run-<ts>.log` (gitignored) with a `last-run.log` symlink; read the log on failure. It pins SSH config with `FEZ_SSH_CONFIG` (`ssh -F`), not `HOME`, because OpenSSH ignores `$HOME/.ssh/config` non-interactively.
- E2E provisioning (`test/e2e/terraform/user_data.sh`) splits the package install into a hard-required core (`cockpit-bridge cockpit-system firewalld`, always present, abort+fail the host if it fails) and the **optional, OS-dependent** `dnf5daemon-server`. `main.tf` passes an `os_family` (`rhel`/`fedora`) template var alongside `login_user`; the script hard-requires `dnf5daemon-server` on Fedora (a silent install regression must surface as `infra fail`, not a false skip) but installs it best-effort on RHEL 10 (`dnf install ... || echo`), because RHEL 10 does not ship it (issue #50). On RHEL 10 the host still readies and runs services/network/firewall; `test_packages` in `lib/capabilities.sh` sees fez exit 9 and records `skip` (the matrix counts only `fail` cells, so a RHEL10 `packages skip` is green). The post-render `user_data.sh` trips shellcheck SC2050 (`[ "rhel" = "rhel" ]`) because the template var is already substituted to a literal; that warning is a rendering artifact, not a bug.

## Env vars

Runtime knobs read from the environment: `FEZ_BRIDGE` (bridge binary path, used by tests), `FEZ_AUDIT` (audit sink, e.g. `file:/path/audit.jsonl`), `FEZ_SSH_CONFIG` (ssh `-F` config), `FEZ_ESCALATION` (privilege-escalation override: `off` disables escalation, any other value forces that single mechanism instead of the default sudo-then-polkit fall-through). Audit records also carry `FEZ_ACTOR`, `FEZ_CORRELATION_ID`, `FEZ_TARGET_HOST`, `FEZ_OPERATION`, `FEZ_UNIT`, etc. Test-only fake-bridge knobs: `FEZ_FAKE_PLAN` (selects the canned dnf5daemon `Goal.resolve` plan: `install`/`small`/`protected`/`cascade`), `FEZ_FAKE_NO_DNF5` (simulates dnf5daemon being absent), `FEZ_FAKE_BRIDGES` (ordered `name:outcome` list of advertised `cockpit.Superuser` mechanisms; unset defaults to `sudo:ok`, empty advertises none), `FEZ_FAKE_DENY_PRIVILEGED` (deny the privileged channel even after a successful `Start`), `FEZ_FAKE_NO_FIREWALLD` (simulates firewalld being absent), `FEZ_FAKE_PANIC` (start the fake firewall in panic-on state), and `FEZ_FAKE_PORT_REMOVED` (drop the drift port `9090/tcp` from the runtime `public` zone, modeling the state after a `remove-port`).

## Conventions

- Error handling: `thiserror` enum + `pub type Result<T>`, propagate with `?`. No `anyhow`.
- Keep async/IO thin; put pure logic in sync helpers. Unit tests inline in `#[cfg(test)] mod tests`.
- `--json` output everywhere uses the `fez/v1` envelope; CLI serialization and bridge request bodies have different `None`/default semantics, so test them separately.
- CLI is self-documenting and stays usable by an LLM the way `git`/`gh` are. The capability registry in `src/capability/mod.rs` is **canonical**: `src/capability/help.rs::inject()` walks the derived clap tree and attaches each descriptor's `long`/`examples` as `long_about`/`after_help`, so `--help`, `fez describe`, `fez man`, and (indirectly) completions all derive from it. When you add or change a command, flag, or arg, update its clap `about` **and** the matching descriptor (summary, long, flags, examples) in the same change. The `services <action> <-> services.<action>` path/id mapping and the example wiring are locked by drift-guard tests in `tests/cli.rs`. `fez guide` renders the exit-code contract from `src/error.rs::EXIT_CODES` (one table, cross-checked against `exit_code()` by a test).

## Notes

- The `packages` capability drives **dnf5daemon** (`org.rpm.dnf.v0`) over the bridge. The target must have the daemon installed and activatable. The package that provides the `org.rpm.dnf.v0` D-Bus service is **`dnf5daemon-server`** (not `dnf5daemon`, which does not exist as a package name); the remediation string in `dependency_missing()` and the install command must use `dnf5daemon-server`. When it is absent, fez returns exit 9 (`dependency-missing`) with remediation in the envelope `detail`. **Availability is OS-dependent: Fedora 41+ ships `dnf5daemon-server`; RHEL 10 does NOT.** RHEL 10 keeps dnf4 as the system manager and the dnf5/dnf5daemon stack targets RHEL 11 (upstream dnf5 PR #780 blocks dnf5 from replacing dnf on RHEL 10), so the package is absent from BaseOS/AppStream and not a repo-enable away. On RHEL 10 `packages` correctly returns exit 9 and callers (and the e2e matrix) treat it as a skip, not a failure (issue #50).
- The `firewall` capability drives **firewalld** (`org.fedoraproject.FirewallD1`) over the bridge. Interface discipline matters: runtime zone reads (`getZones`/`getServices`/`getPorts`/`getInterfaces`/`getSources`) go on `org.fedoraproject.FirewallD1.zone`, while `getDefaultZone`/`listServices`/`queryPanicMode` and mutations go on the root `org.fedoraproject.FirewallD1`; calling a method on the wrong interface is a real-firewalld `UnknownMethod` (the original cause of issue #33, where `getZones` was wrongly sent to the root interface). `list`/`show`/`services` are fully unprivileged. `status` is **mostly** unprivileged but escalates for one thing: the permanent-config read it does to compute runtime-vs-permanent drift. firewalld classifies permanent `config`/`config.zone` reads under `PK_ACTION_CONFIG` (`auth_admin_keep` on server **and** desktop installs), so that read must arrive on a privileged channel; `status` opens a second, privileged channel just for it (issue #34). A host with no escalation mechanism therefore fails `status` with exit 11 rather than silently reporting empty drift. Mutations (add/remove service/port, set-default-zone, reload, confirm, panic, masquerade) escalate. fez holds no state: mutations apply to **runtime only** and persistence happens exclusively via `fez firewall confirm` (firewalld's `runtimeToPermanent`); `status` recomputes drift live each call. A pure protected-op guard in `safety.rs` refuses lockout-prone ops (removing the session ssh service/port, any default-zone change, `panic on`, a drift-discarding `reload`, and disabling masquerade) without `--force` (exit 8); enabling masquerade is unguarded, disabling is protected (exit 8). When firewalld is absent, fez returns exit 9 (`dependency-missing`); the package to install is `firewalld`.
